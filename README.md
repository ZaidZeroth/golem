# MANX MUDMEN - Hop Tu Naa Hackathon

A framework-free browser prototype for exploring Golem's clay-clod world and pairwise word combinations.

## Run locally

Open `index.html` in a current browser. There is no build step, package install, or external dependency. For a local browser session, serve this directory on loopback:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Then open `http://127.0.0.1:8765/`.

## Current interaction draft

- The map starts with one square clod for each currently playable base word. `AND`, `OR`, `IN`, `ME`, and `FIT` are excluded from both the world and endless bank for now; they appear as non-interactive clay tokens in a `Coming soon` panel below the game. The other clods are randomized in the forest clearing with open space between them. Resizing the viewport preserves their relative positions and only nudges a clod if the resized clearing or another clod makes its spot invalid. The endless bank remains the source for adding more copies.
- The MANX MUDMEN - Hop Tu Naa Hackathon title and endless base-element bank sit in a translucent in-world HUD over the garden canvas. The bank shows every base element as a clay sprite with its word overlaid, matching the world clods and scaling to the world grid cell size. Pointer-dragging a bank sprite shows a matching ghost continuously within the game surface; the point grabbed remains aligned when it lands in the world. Drop it in the garden to add a copy or directly onto a world clod to combine; the pointer position is used for target detection so the sprite's grab offset does not prevent combining. Dropping it back in the top panel cancels the copy and leaves the bank unchanged. Drag an existing world clod back anywhere into the top panel to discard that clod. Clicking a bank item still adds a copy at the garden centre. The base element is displayed as `eye`.
- Clay and element sprites are tinted on offscreen copies, so filters affect opaque pixels while preserving transparent edges and shading. Uncolored sprites receive a 50% dark overlay; color overlays use 25% opacity, except white (red + green + blue), which uses 32%. In-world words and page headings use Creepster; the detail panel keeps Atkinson Hyperlegible Next for longer reading.
- Untyped and non-symbol clods use the Artist's new ink-outlined clay lump (`assets/golem-clay-lump-ink-outline-64px.png`). Its tint cache is cleared when the source image loads, so an early palette render cannot leave blank sprite copies behind. The earlier clay-lump source is kept alongside it.
- The 64px clay eye, open-hand, fist, feet, and supported direction-arrow sprites appear in matching world clods and bank squares. Every square keeps its lowercase word over the sprite. The supplied hand and fist art faces left: LEFT HAND/FIST stays unmirrored, while the default and RIGHT HAND/FIST are horizontally mirrored. The supplied arrow art faces right: RIGHT stays as supplied; LEFT rotates 180° and is vertically mirrored for consistent shading; UP rotates 90° counter-clockwise; DOWN is the vertical mirror of UP.
- Clicking a world square only selects it; clicking another never combines them. Drag one square onto another to compose a recognized expression. The target remains in place; the dropped square is consumed. Exact target-then-dropped construction order is retained even when the square face uses a normalized reading; the proposed double-negation simplification reduces back to the elemental `RIGHT`.
- Dropping an operator element into an expression that already contains that same operator is unsupported, except for the explicit `NOT + HOLD → NOT HOLD` recipe. `HOLD` is constructed from `WHILE + FIST`, and `FIST` already contains `NOT`; this one negation is intentionally allowed. Other repeated `WHILE`, `DO`, or operator words remain blocked. Separate completed sense-response pathways may each contain their own operators.
- Clay can be dropped at any continuous position whose center is inside the forest clearing, without snapping to grid cells. If a square would collide with another, the pointer-up handler searches for the nearest open position around it. There is no fixed clay-count limit; another square is rejected only when the continuous 2–4px clearing search finds no open position.
- The draft recognizes NOT + RED; provisional RGB channel unions (red + green → yellow, red + blue → magenta, green + blue → cyan, then any full RGB union → white); DO + RED → be red; NOT + HAND → FIST; NOT + RIGHT HAND → LEFT HAND (and the converse); provisional NOT + FIST → HAND; RIGHT + NOT → LEFT; NOT + UP → DOWN; and a second NOT over LEFT → RIGHT. LEFT/RIGHT hands and fists can be formed. The direction and hand rules remain proposals.
- EYE can combine with color filters, but not directions. Build `WHILE + EYE → SEE` first, then combine SEE with UP/DOWN/LEFT/RIGHT to form a directional sensor: true when another clay square is in the same straight lane in that direction within three cells. WHILE can combine with HAND, FIST, or a filtered sight expression; for example, `(WHILE + (EYE + (NOT + RED)))` reads “while seeing clay that does not contain red pigment.” `WHILE + RIGHT HAND` and `(WHILE + HAND) + RIGHT` both form a right-side touch sensor; the matching LEFT constructions sense only clods on that side. Sensory and motive verbs imply WHILE or DO on the square face; the construction and natural-language inspector retain those operators. Occlusion is not modeled.
- DO can form the suggested HAND, FIST, RED, EYE, and directed hand/fist action phrases. Adding LEFT or RIGHT to a GRAB or DROP expression selects the side of the golem the action targets, independently of which hand is used. FEET no longer combines with LEFT or RIGHT. DO + FEET → MOVE remains a tentative random-walk interpretation; combining that MOVE with a direction forms MOVE LEFT, MOVE RIGHT, MOVE UP, or MOVE DOWN, and the directional result attempts slow movement in that direction. Random movement tries other cardinal directions immediately when its current direction is blocked, and reports blocked only when every direction is unavailable. These movement behaviors are provisional prototype experiments and do not settle the game's movement rules. Adding NOT to the eye action or using DO + (NOT + EYE) forms a close-eyes phrase. AND/OR and IN + ME are not playable while their source words remain in the coming-soon panel. A recognized sense/action pair is displayed as its words in sequence, such as `see then move`, rather than a generic `golem` label.
- `NOT + HAND → FIST`; adding LEFT or RIGHT to FIST selects a hand, such as `RIGHT + FIST → RIGHT FIST`. `RIGHT FIST + DO → RIGHT GRAB` chooses the right hand but can grab from any adjacent side. Adding a direction to GRAB selects the source side independently: `RIGHT GRAB + LEFT → RIGHT GRAB LEFT` grabs from the golem's left adjacency into its right hand. `FIST + DO → GRAB` uses a randomly chosen free hand and can grab from any adjacent side; `GRAB + LEFT` restricts the source to the left but still chooses a free hand. Each hand holds at most one square, and a full selected hand cannot grab. Held clay is removed from the garden and shown as a sprite and label at 51% of the golem tile size over that hand. `DO + HAND → DROP` chooses a randomly selected hand that is holding clay; `DO + RIGHT HAND → RIGHT DROP` selects the right hand. Adding a direction chooses the drop side independently, so `RIGHT DROP + LEFT → RIGHT DROP LEFT` drops the right-hand clod on the golem's left side, and `LEFT DROP + RIGHT → LEFT DROP RIGHT` does the reverse. Unqualified DROP still places the clod beside the selected hand. Dropped clay is restored to the garden when possible, using the clearing's nearest-open-space placement search. These continuous grab/drop actions are a local prototype interpretation.
- `WHILE + FIST → HOLD` is true while either hand holds clay. `WHILE + LEFT FIST` and `WHILE + RIGHT FIST` check the corresponding hand. The same held-item state drives the hand overlay and the HOLD glow/status.
- `WHILE + EYE → SEE` reads “while seeing anything.” `WHILE + HAND → TOUCH` reads “while touching.” `NOT + TOUCH → NOT TOUCH` is true while no other clay is adjacent; `NOT + SEE → NOT SEE` is true while there is no clay within three cells. `DO + EYE → LOOK` reads “look.” `WHILE + EYE` senses any other clay square within three cells (center-to-center); `WHILE + EYE + RED/GREEN/BLUE` and mixed-color filters test for matching pigment within the same three-cell range. Directional `SEE UP/DOWN/LEFT/RIGHT` checks for another clay square in that straight lane within three cells and activates the same glow. Because the garden allows free placement, touch checks the edge gap between square clods rather than assuming grid-aligned centers; it counts clods with up to an 8px gap on each axis, including diagonals. `WHILE + RIGHT HAND` and `(WHILE + HAND) + RIGHT` both test clods on the right side, with the corresponding LEFT recipes testing the left side. `WHILE + HAND + RED/GREEN/BLUE` evaluates true only when adjacent clay contains that pigment; mixed-color filters match when all selected color channels are present. `HAND + CLOD` creates a hand clod; `(WHILE + HAND) + (HAND + CLOD)` becomes true only when a hand clod is adjacent. Color + CLOD creates a colored clod, such as `RED + CLOD → RED CLOD`. `TOUCH RED/GREEN/BLUE` is active: it becomes true only when adjacent clay contains the requested color channels. The mixed-color touch filters use the same channel-inclusion check. Either true active sensor shows the same filled, pulsing circular glow. A combined `SEE/NOT SEE + MOVE` or `TOUCH/NOT TOUCH + MOVE` expression runs its currently composed movement response only while that sense is true; moving out of range or adjacency, or entering range/adjacency for a negated sense, stops the response. The glow is drawn behind the square, separate from the square selection outline; a still glow is used when reduced motion is requested. Sensors update as clods move, are dragged, or are added. Releasing a dragged clod restarts the behavior timer and reevaluates the current sense; the response still pauses when the sense is false or its path is blocked by a clod or the clearing edge. These are narrow prototype behaviors, not general rules for WHILE/DO activation, pattern matching, or line-of-sight occlusion.
- There are no separate trash or refresh controls. The entire top element panel acts as the discard area for world clods; the base-element bank itself remains endless and unchanged.
- The Artist's front-facing golem variant (`assets/golem-mini-golem-front-variant-64px.png`) is used as a visual state for recognized WHILE sense expressions, DO motive expressions, and complete sense/action pairs. The lowercase expression stays over the forehead, the face remains inside the same square, and an expression's color intent tints the sprite. A brightness/contrast pass and soft warm rim increase value separation against the forest and clay. The responsive square size ranges from 44px to 64px. This is a visual exploration; active prototype responses include supported WHILE/NOT senses paired with movement, GRAB, or DROP.
- The buildable-recipe panel is removed; expressions are discovered by combining clods in the world.
- Select a square to inspect its exact construction and natural-language layer. Selection alone does not combine; combination requires dragging and dropping onto another square. Filler labels such as “entity” and “compound” are omitted.

## Prototype boundary and open rules

The added combinations are provisional readings of Designer suggestions. `DO + FEET → MOVE` is a tentative random-walk experiment; adding a direction to MOVE produces a direct directional movement experiment, including down. FEET + LEFT/RIGHT is intentionally unsupported. Random movement tries another open cardinal direction when a step is obstructed and stays put only if all directions are blocked. Grab/drop and HOLD behavior also run only as local prototype interpretations, not settled language rules. A complete sense/response pair can be combined with another complete pair to create a compound golem with multiple independent conditional pathways. Each pathway retains its own sensor state and action cooldown. Active action pathways run in construction order; if multiple movement pathways are true at once, the first active movement pathway in construction order controls that tick. `NOT + HOLD` is true while neither hand contains a held clod, and can be paired with GRAB or another supported response. The local `SEE/NOT SEE + MOVE` and `TOUCH/NOT TOUCH + MOVE` pairs run only while their corresponding positive or negated sensor is true. Other WHILE conditions, pattern matching, close-eyes behavior, structural inspection, and FIT are not simulated. AND, OR, IN, ME, FIT, COMBINE, and SPLIT are temporarily unavailable in the playable world and bank and are displayed as coming-soon tokens. Combining clods held in both hands and splitting/undo remain unimplemented. AND/OR and other direction readings are composition-only; no sensor evaluates them. The directed RGB color recipes are represented as expressions and tinted with the shared clay sprite; they do not execute a golem action or settle activation. New unpigmented clods use a dark gray tint. All world word faces and construction-tree words render in lowercase. The clod compound construction order remains visible in the inspector.

The map, fixed-size squares, compact lowercase face text, dark gray unpigmented clay, RGB-derived color states, shared clay silhouette, and detail panel follow the current Artist direction. The mini-golem sprite and its forehead word placement are a visual implementation exploration, not final art approval. Movement rules remain open for further design discussion.
