# Golem: The Word Workshop

A framework-free browser prototype for exploring Golem's square-block world and pairwise word combinations.

## Run locally

Open `index.html` in a current browser. There is no build step, package install, or external dependency. For a local browser session, serve this directory on loopback:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Then open `http://127.0.0.1:8765/`.

## Current interaction draft

- The map starts with one square block for each currently playable base word. `BLOCK`, `AND`, `OR`, `IN`, `ME`, and `FIT` are excluded from both the world and endless bank for now; they appear as non-interactive clay tokens in a `Coming soon` panel below the game. The other blocks are randomized in the forest clearing with open space between them. Resizing the viewport preserves their relative positions and only nudges a block if the resized clearing or another block makes its spot invalid. The endless bank remains the source for adding more copies.
- The GOLEM title and endless base-element bank sit in a translucent in-world HUD over the garden canvas. The bank shows every base element as a clay sprite with its word overlaid, matching the world squares and scaling to the world grid cell size. Pointer-dragging a bank sprite shows a matching ghost continuously within the game surface; the point grabbed remains aligned when it lands in the world. Drop it in the garden to add a copy or directly onto a world block to combine; the pointer position is used for target detection so the sprite's grab offset does not prevent combining. Dropping it back in the top panel cancels the copy and leaves the bank unchanged. Drag an existing world block back anywhere into the top panel to discard that block. Clicking a bank item still adds a copy at the garden centre. The base element is displayed as `eye`.
- The shared clay sprite is tinted on an offscreen copy, so color filters affect its opaque pixels while preserving transparent edges and shading. Each colored tint uses 25% overlay opacity. In-world words and page headings use Creepster; the detail panel keeps Atkinson Hyperlegible Next for longer reading.
- Untyped and non-symbol blocks use the Artist's new ink-outlined clay lump (`assets/golem-clay-lump-ink-outline-64px.png`). Its tint cache is cleared when the source image loads, so an early palette render cannot leave blank sprite copies behind. The earlier clay-lump source is kept alongside it.
- The 64px clay eye, open-hand, fist, feet, and supported direction-arrow sprites appear in matching world blocks and bank squares. Every square keeps its lowercase word over the sprite. LEFT HAND uses a horizontally mirrored open-hand sprite; RIGHT HAND uses the standard open-hand sprite. The down-arrow asset stays unused because DOWN is not a current element.
- Clicking a world square only selects it; clicking another never combines them. Drag one square onto another to compose a recognized expression. The target remains in place; the dropped square is consumed. Exact target-then-dropped construction order is retained even when the square face uses a normalized reading; the proposed double-negation simplification reduces back to the elemental `RIGHT`.
- Clay can be dropped at any continuous position whose center is inside the forest clearing, without snapping to grid cells. If a square would collide with another, the pointer-up handler searches for the nearest open position around it. There is no fixed clay-count limit; another square is rejected only when the continuous 2–4px clearing search finds no open position.
- The draft recognizes NOT + RED; provisional RGB channel unions (red + green → yellow, red + blue → magenta, green + blue → cyan, then any full RGB union → white); DO + RED → be red; NOT + HAND → FIST; HAND + HAND → COMBINE; provisional NOT + FIST → HAND; RIGHT + NOT → LEFT; and a second NOT over LEFT → RIGHT. LEFT/RIGHT hands and fists can be formed. The direction and hand rules are proposals; UP + NOT remains unimplemented.
- EYE can combine with color or direction filters. WHILE can combine with HAND, FIST, or a filtered sight expression; for example, `(WHILE + (EYE + (NOT + RED)))` reads “while seeing clay that does not contain red pigment.” Sensory and motive verbs imply WHILE or DO on the square face; the construction and natural-language inspector retain those operators. `WHILE + EYE + UP` reads `SEE UP` and is a provisional directional sensor: true when another clay square is in the same lane directly above within three cells. LEFT and RIGHT check corresponding horizontal lanes; occlusion is not modeled.
- DO can form the suggested HAND, FIST, RED, EYE, COMBINE, and directed hand/fist action phrases. The movement exploration recognizes FEET + LEFT → LEFT FEET → DO + LEFT FEET → MOVE LEFT and FEET + RIGHT → RIGHT FEET → DO + RIGHT FEET → MOVE RIGHT. It also recognizes DO + FEET → MOVE as tentative random cardinal wandering, then direction + MOVE as a way to form MOVE LEFT, MOVE RIGHT, or MOVE UP. MOVE UP attempts slow upward movement. Random movement tries the other cardinal directions immediately when its current direction is blocked, and reports blocked only when every direction is unavailable. These movement behaviors are provisional prototype experiments and do not settle the game's movement rules. Adding NOT to the eye action or using DO + (NOT + EYE) forms a close-eyes phrase. AND/OR and IN + ME are not playable while their source words remain in the coming-soon panel. A recognized sense/action pair is displayed as its words in sequence, such as `see then move`, rather than a generic `golem` label.
- `WHILE + EYE → SEE` reads “while seeing anything.” `WHILE + HAND → TOUCH` reads “while touching.” `NOT + TOUCH → NOT TOUCH` is true while no other clay is adjacent; `NOT + SEE → NOT SEE` is true while there is no clay within three cells. `DO + EYE → LOOK` reads “look.” `WHILE + EYE` senses any other clay square within three cells (center-to-center); directional `SEE UP/LEFT/RIGHT` checks for another clay square in that straight lane within three cells. `WHILE + HAND` is true when another clay square is in one of the eight surrounding cell positions (including diagonals). `SEE RED/GREEN/BLUE` and `TOUCH RED/GREEN/BLUE` (including mixed color states) are recognized as proposed readings, such as “while seeing red pigment”; color-filtered behavior is not simulated. Either true active sensor shows the same filled, pulsing circular glow. A combined `SEE/NOT SEE + MOVE` or `TOUCH/NOT TOUCH + MOVE` expression runs its currently composed movement response only while that sense is true; moving out of range or adjacency, or entering range/adjacency for a negated sense, stops the response. The glow is drawn behind the square, separate from the square selection outline; a still glow is used when reduced motion is requested. Sensors update as squares move, are dragged, or are added. Releasing a dragged block restarts the behavior timer and reevaluates the current sense; the response still pauses when the sense is false or its path is blocked by a square or the clearing edge. These are narrow prototype behaviors, not general rules for WHILE/DO activation, pattern matching, or line-of-sight occlusion.
- There are no separate trash or refresh controls. The entire top element panel acts as the discard area for world blocks; the base-element bank itself remains endless and unchanged.
- The Artist's front-facing golem variant (`assets/golem-mini-golem-front-variant-64px.png`) is used as a visual state for recognized WHILE sense expressions, DO motive expressions, and complete sense/action pairs. The lowercase expression stays over the forehead, the face remains inside the same square, and an expression's color intent tints the sprite. A brightness/contrast pass and soft warm rim increase value separation against the forest and clay. The responsive square size ranges from 44px to 64px. This is a visual exploration; only `WHILE + EYE/HAND`, their `NOT` forms, and their paired movement responses run in this prototype.
- The buildable-recipe panel is removed; expressions are discovered by combining blocks in the world.
- Select a square to inspect its exact construction and natural-language layer. Selection alone does not combine; combination requires dragging and dropping onto another square. Filler labels such as “entity” and “compound” are omitted.

## Prototype boundary and open rules

The added combinations are provisional readings of Designer suggestions. The requested `DO + LEFT FEET` example executes as slow leftward movement; rightward movement and random-walk interpretations execute only as local prototype experiments, not settled language rules. Random movement tries another open cardinal direction when a step is obstructed and stays put only if all directions are blocked. The local `SEE/NOT SEE + MOVE` and `TOUCH/NOT TOUCH + MOVE` pairs run only while their corresponding positive or negated sensor is true. This is prototype behavior, not a settled language rule. Other WHILE conditions, pattern matching, close-eyes behavior, structural inspection, and FIT are not simulated. BLOCK, AND, OR, IN, ME, and FIT are temporarily unavailable in the playable world and bank and are displayed as coming-soon tokens. It also does not implement SPLIT/undo, because history behavior remains unresolved. AND/OR and other direction readings are composition-only; no sensor evaluates them. The directed RGB color recipes are represented as expressions and tinted with the shared clay sprite; they do not execute a golem action or settle activation. New unpigmented blocks use a dark gray tint. All world word faces and construction-tree words render in lowercase. The square-block construction order remains visible in the inspector.

The map, fixed-size squares, compact lowercase face text, dark gray unpigmented clay, RGB-derived color states, shared clay silhouette, and detail panel follow the current Artist direction. The mini-golem sprite and its forehead word placement are a visual implementation exploration, not final art approval. Movement rules remain open for further design discussion.
